# Контур — аналитика риска оттока

Веб-панель и REST API для оценки риска непродления услуг и приоритизации работы команды удержания. Приложение принимает снимок аккаунтов, услуг и транзакций, рассчитывает объяснимые сигналы и денежную оценку риска, а настройки модели хранит в SQLite.

## Возможности

- Панель с рейтингом клиентов, фильтром по риску, постраничным просмотром и сортировкой по ID, email, балансу, пополнениям и оценке.
- Карточка клиента с причинами оценки, услугами, балансом и прогнозом выручки под риском.
- Изменение весов модели без перезагрузки страницы; значения сохраняются в SQLite.
- JSON-снимки с проверкой ссылок, типов, сумм, статусов, дубликатов и лимитов до атомарной замены данных.
- Сводная аналитика и Prometheus-метрики, основанные на одном расчёте.
- Вход администратора, ограничение частоты попыток, сессия в HttpOnly cookie, защитные HTTP-заголовки.
- Светлая и тёмная темы, адаптивная панель, клавиатурная навигация и учёт `prefers-reduced-motion`.

Оценка — это детерминированная эвристика для сортировки обращений, а не статистически обученная вероятность оттока. Потенциальная потеря оценивает три месяца выручки активных и приостановленных услуг за вычетом доступного баланса и умножает остаток на коэффициент категории риска. Суммы в исходном JSON задаются в евроцентах; интерфейс форматирует их в евро.

## Технологии и структура

- Python 3.12, FastAPI, Pydantic и Uvicorn.
- SQLite: снимок, веса, сессии и ограничения входа.
- HTML, CSS и vanilla JavaScript: без сборщика и внешних frontend-зависимостей.
- Docker Compose: один контейнер приложения; SQLite хранится в файле `data/churn.db` на хосте.

```text
code.py                 совместимая точка входа Uvicorn
churnrisk/api.py        HTTP-маршруты, сессии, заголовки и лимиты тела
churnrisk/domain.py     признаки, оценка риска и аналитика
churnrisk/storage.py    SQLite, валидация и атомарная замена снимка
churnrisk/schemas.py    входные и выходные схемы API
static/                 стили, скрипты и страница входа
templates/index.html    панель аналитики
tests/                  доменные и API-проверки
```

## Запуск через Docker

Требуются Docker Desktop с Compose v2 и свободный порт 8000.

```powershell
Copy-Item .env.example .env
```

Укажите уникальный пароль администратора в `.env`, затем запустите:

```powershell
docker compose up --build -d
```

По умолчанию Compose подключает локальный каталог `data` к `/app/data` и использует имеющийся `data/churn.db`. При необходимости задайте `DATA_DIR` в `.env` как путь к другому каталогу данных.

Откройте <http://localhost:8000>. Входные данные берутся из `ADMIN_USERNAME` и `ADMIN_PASSWORD` в `.env`. Compose подключает каталог `data` с хоста; существующий `data/churn.db` используется на месте. Для локального HTTP `COOKIE_SECURE=false`; при размещении за HTTPS установите `COOKIE_SECURE=true` и используйте HTTPS reverse proxy.

Полезные команды:

```powershell
docker compose ps
docker compose logs -f churn-risk
docker compose down
```

Контейнер запускается от непривилегированного пользователя. SQLite подключена из `data/churn.db` и остаётся на хосте после `docker compose down` и пересоздания контейнера. Не удаляйте каталог `data` и файл базы, пока данные нужны.

## Локальная разработка

Требуется Python 3.12 или новее.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
$env:ADMIN_USERNAME = "admin"
$env:ADMIN_PASSWORD = "set-a-unique-local-password"
python -m uvicorn code:app --reload
```

По умолчанию SQLite создаётся в `data/churn.db`. Путь можно переопределить через `DATABASE_PATH`. При первом запуске пустой базы приложение создаёт восемь синтетических демонстрационных аккаунтов. Загрузка снимка полностью заменяет аккаунты, услуги и транзакции в одной транзакции; веса модели и сессии сохраняются.

## Тесты

Тесты используют временную SQLite-базу и отдельные тестовые учётные данные; проектную базу и `.env` они не меняют.

```powershell
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -t . -v
ruff check code.py churnrisk tests
ruff format --check code.py churnrisk tests
```

## API

- Swagger UI: <http://localhost:8000/api/v1/docs> (local Swagger UI 5.34.0 assets; license in `static/vendor/swagger-ui/LICENSE`)
- OpenAPI JSON приложения: `/api/v1/openapi.json`
- Контракт в репозитории: [`openapi.yaml`](openapi.yaml)
- Проверка готовности: `GET /health` (публичный endpoint без бизнес-данных)
- Метрики Prometheus: `GET /metrics`

Маршруты `/api/v1/customers`, `/api/v1/analytics/summary`, `/api/v1/model/settings` и `/api/v1/source/snapshot` требуют входа. Войдите через `POST /api/v1/auth/login`; API устанавливает сессионную cookie. Список и карточка клиента, настройки и загрузка снимка доступны только с действующей cookie.

Денежные поля `balance`, `withdrawBalance`, `bonusBalance`, `totalReplenished`, `price` и `amount` передаются целыми неотрицательными евроцентами. `bonusBalance` включается в доступный остаток, только если `bonusState` истинно. Статусы услуг: `active`, `suspended`, `prolong_wait`, `deleted`, `blocked`; `suspended` продолжает учитываться в выручке. Периоды: `hour`, `week`, `month`, `quarter_year`, `half_year`, `year`. `prolong_wait` учитывается в прогнозе как ожидание оплаты в пределах пятидневного льготного периода. Аккаунт без услуг и транзакций получает статус `unrated`.

Минимальный формат импорта:

```json
{
  "accounts": [{"id": 42, "email": "client@example.org", "balance": 8500, "bonusBalance": 300, "bonusState": true, "totalReplenished": 42000}],
  "services": [{"id": "s-1", "accountId": 42, "name": "Виртуальный сервер", "status": "active", "price": 2400, "paymentTerm": "month", "autoprolong": false, "expiresAt": "2026-11-02T00:00:00Z"}],
  "transactions": []
}
```

Допускается имя коллекции `users` вместо `accounts`, а также поля связи `userId` или `account_id`. Снимок ограничен 32 MiB; лимиты записей и полная схема описаны в OpenAPI. Некорректный снимок отклоняется целиком, предыдущие данные остаются на месте.

## Расширение модели

Чтобы добавить булев сигнал, добавьте функцию определения и пояснения, затем `Feature` в реестр `FEATURES` в `churnrisk/domain.py`. Реестр формирует подписи, значения по умолчанию и список допустимых настраиваемых весов для панели и API.

## Ограничения

- Нет внешнего провайдера аутентификации/OIDC и управления несколькими ролями; используется один администратор из переменных окружения.
- SQLite подходит для локального запуска и небольшой демонстрации; горизонтальное масштабирование сервиса не входит в эту архитектуру.
- `GET /metrics` отдаёт агрегированные показатели без cookie, но персональные данные в метрики не попадают.
- Срок продления и оценки зависят от корректности дат и периодов в загружаемом снимке.
