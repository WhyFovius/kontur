# Контур — аналитика риска оттока

Веб-панель и REST API для оценки риска непродления услуг хостинга и приоритизации работы команды удержания. Приложение принимает JSON-снимок аккаунтов, услуг и транзакций, рассчитывает объяснимый скор риска и денежную оценку потерь, а настройки модели хранит в SQLite — изменение весов в панели пересчитывает рейтинг без перезагрузки и переживает перезапуск.

## Быстрый старт

Нужен Docker Desktop / Docker Engine с Compose v2.

```bash
cp .env.example .env          # в Windows PowerShell: Copy-Item .env.example .env
# укажите в .env уникальный ADMIN_PASSWORD
docker compose up --build -d
```

Откройте **http://localhost:8000** и войдите под `ADMIN_USERNAME` / `ADMIN_PASSWORD` из `.env`.

> Порт по умолчанию — **8000** (не 8080). Чтобы публиковать на другом порту хоста, задайте в `.env` например `PORT=8080` — тогда панель будет на http://localhost:8080.

При первом запуске с пустой базой приложение само создаёт восемь синтетических демонстрационных аккаунтов — панель не будет пустой. База лежит в `data/churn.db` на хосте и сохраняется между перезапусками контейнера.

Остановка и логи:

```bash
docker compose ps
docker compose logs -f churn-risk
docker compose down
```

## Возможности

- **Рейтинг клиентов**: скор 0–100, уровни риска (низкий / средний / высокий / без оценки), человекочитаемые причины, фильтр по уровню риска, пагинация и сортировка по ID, email, балансу, сумме пополнений и скору — по возрастанию и по убыванию.
- **Карточка клиента**: услуги, балансы, вклад каждого признака в скор, выручка и потенциальная потеря.
- **Модель в панели**: веса шести признаков меняются слайдерами и применяются без перезагрузки страницы; сохраняются в SQLite и действуют после перезапуска.
- **Динамика оттока «факт vs прогноз»**: исторические удаления услуг за 90 дней визуально отделены от прогноза (услуги под риском и ожидаемые непродления на 90 дней вперёд).
- **Денежная оценка риска** с учётом стоимости услуг, доступного баланса и категории риска.
- **Загрузка снимков** из панели (файл или drag-and-drop) и по API: полная валидация и атомарная замена данных — битый снимок не трогает текущие данные.
- **Аутентификация обязательна**: пароль администратора, опционально OpenID Connect (SSO), для программных клиентов — HTTP Basic. Без входа бизнес-данные недоступны.
- **Prometheus-метрики** из того же расчёта, что и панель.
- Панель автообновляет данные каждые 10 секунд; светлая и тёмная темы, адаптивная вёрстка, клавиатурная навигация, поддержка `prefers-reduced-motion`.

## Модель риска

Скор — детерминированная объяснимая эвристика для приоритизации обращений, **не** обученная вероятность оттока. Каждый признак — булев сигнал с настраиваемым весом:

| Признак (`key`) | Сигнал | Вес по умолчанию |
| --- | --- | ---: |
| `expiring_without_autoprolong` | Услуга скоро заканчивается и у неё нет автопродления | 25 |
| `insufficient_funds` | Доступного баланса не хватит на ближайшее продление | 25 |
| `prolong_wait` | Есть услуга в статусе «ожидает оплаты» | 25 |
| `failed_transactions` | Были незавершённые/неудачные платежи | 12 |
| `deleted_services` | Клиент уже удалял услуги | 8 |
| `balance_pressure` | Месячная стоимость услуг велика относительно истории пополнений | 5 |

Скор = 100 × (сумма весов активных сигналов) / (сумма всех положительных весов). Пороги: **≥ 65 — высокий**, **≥ 35 — средний**, ниже — низкий. Аккаунт без услуг и транзакций получает `unrated`. Подписи причин генерируются из тех же сигналов — скор всегда можно объяснить.

**Денежная оценка.** Месячная выручка клиента — стоимость активных и приостановленных услуг, приведённая к месяцу по `paymentTerm`. Потенциальная потеря на горизонте 3 месяцев:

```
estimatedLoss = max(0, 3 × месячная выручка − доступный баланс) × коэффициент риска
```

Коэффициент риска: высокий — 0,80; средний — 0,45; низкий — 0,15. Доступный баланс = `balance` + `bonusBalance` (бонус учитывается только при `bonusState = true`). Все суммы в API и снимках — целые **евроценты**; панель форматирует их в евро.

**Прогноз.** `churnForecast` считает услуги, которые могут не продлиться к горизонтам 0/7/14/21/30 дней (ожидающие оплаты + истекающие без автопродления). Отдельный эндпоинт динамики раскладывает факт и прогноз по бакетам 90 дней назад/вперёд; ожидаемые непродления взвешены теми же коэффициентами риска.

## Панель

Три страницы рабочего пространства:

- **Обзор** — KPI портфеля, распределение по уровням риска, поток выручки под риском по срокам окончания услуг, график «факт vs прогноз», калькулятор спасённой выручки, качество данных и очередь «на сегодня» из клиентов высокого риска.
- **Клиенты** — рейтинг с фильтрами и сортировкой, раскрывающиеся карточки с разбором скора, сохранённые виды (хранятся локально в браузере).
- **Модель риска** — слайдеры весов (пересчёт на лету, сохранение по кнопке), локальный what-if сценарий без записи на сервер.

Интерфейс — React 19 + TypeScript + Framer Motion, дизайн-система Material Design 3 Expressive в фирменном стиле Aéza. Собранный бандл коммитится в `static/app` и раздаётся FastAPI, поэтому на сервере Node не нужен; если бандла нет, отдаются легаси-страницы из `templates/` и `static/login.html`.

## Архитектура

```
Снимок JSON ──► нормализация и валидация ──► SQLite (атомарная замена)
                                                  │
Веса из панели ──► PATCH /model/settings ──► SQLite (settings)
                                                  ▼
                              analyze(): признаки → скор → деньги
                                                  ▼
                     API рейтинга · сводка · динамика · /metrics · панель
```

Анализ кэшируется по версиям снимка и модели: повторные запросы не пересчитывают портфель, пока данные или веса не изменятся.

| Путь | Назначение |
| --- | --- |
| `code.py` | Точка входа Uvicorn (`uvicorn code:app`) |
| `churnrisk/api.py` | HTTP-маршруты, сессии, заголовки безопасности, лимиты тела запроса |
| `churnrisk/domain.py` | Признаки, скор, денежная оценка, сводная аналитика и динамика оттока |
| `churnrisk/snapshot.py` | Нормализация снимка (алиасы полей и коллекций) |
| `churnrisk/storage.py` | SQLite: снимок, настройки, сессии, валидация и атомарная замена |
| `churnrisk/security.py` | Проверка пароля администратора (scrypt) |
| `churnrisk/oidc.py` | Опциональный OIDC-вход (Authorization Code + PKCE, проверка ID-токена по JWKS) |
| `churnrisk/schemas.py` | Входные и выходные схемы API (Pydantic) |
| `churnrisk/config.py` | Пути, лимиты, срок сессии |
| `frontend/` | Исходники React-панели (Vite, Framer Motion, Material Web) |
| `static/app/` | Собранный фронт, раздаётся FastAPI на `/` и `/login` |
| `openapi.yaml` | Контракт API в репозитории (сверяется тестом с живым роутером) |
| `tests/` | Доменные тесты, API-тесты и тесты OIDC-потока |
| `REVIEW.md` | Журнал редизайна и принятых решений |

Стек: Python 3.12, FastAPI, Pydantic v2, Uvicorn, SQLite; фронт — React 19, TypeScript, Vite 6, Framer Motion 12, `@material/web`. OIDC работает на `httpx` + `PyJWT[crypto]`; импорты ленивые — без настроенного провайдера приложение стартует как обычно.

- Swagger UI: http://localhost:8000/api/v1/docs (ассеты Swagger UI лежат в репозитории, CDN не используется)
- OpenAPI JSON: `/api/v1/openapi.json`; контракт в репозитории: [`openapi.yaml`](openapi.yaml)

| `GET` | `/api/v1/model/settings` | сессия / Basic | Веса признаков, подписи и пороги |

Вход по паролю защищён ограничением попыток (после серии неудач — `429` с `Retry-After`). Для программных клиентов и коллекторов тот же администратор принимается по `Authorization: Basic`.
