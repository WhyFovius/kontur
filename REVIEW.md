# Ревью и отчет о редизайне платформы аналитики риска оттока

## Дополнение 18 — этапы 1–2 без Rust: prepared-анализ, кэши и PostgreSQL

По решению пользователя реализованы только первые два этапа усиления из дополнения 17. PyO3, Axum-sidecar и полный Rust-rewrite не трогались.

### Этап 1: оптимизация текущего Python/FastAPI

- Домен больше не вызывает callback-признаки и не сканирует услуги отдельно под каждый сигнал. `analyze_prepared()` за один проход по `ServiceFact` считает выручку, сумму ближайших продлений, `prolong_wait`, удалённые услуги, ближайшее окончание и все шесть сигналов; причины, пороги 35/65, коэффициенты потерь 0,80/0,45/0,15 и денежная формула сохранены. `summary`, churn timeline, Rescue Queue и alert candidates используют epoch-факты вместо повторного парсинга дат.
- При `PUT /source/snapshot` услуги теперь материализуются не только как JSON, но и как типизированные колонки статуса, цены, месячной выручки, автопродления и epoch-дат. Транзакции для модели агрегируются SQL-запросом до количества и флага `not_performed`; миллион JSON-транзакций при смене весов заново не парсится. Старые SQLite-базы получают колонки/индексы и backfill при старте, все строки снимка кодируются в JSON до первого `DELETE`.
- Кэш разделён: prepared-снимок живёт по `snapshot_version`, анализ — по `(snapshot_version, model_version)`. Пересчёт защищён single-flight и вынесен из event loop. Истечение TTL работает как stale-while-revalidate одним фоновым потоком; смена снимка или весов не отдаёт stale-результат и считается синхронно в worker. Поверх анализа кэшируются индекс клиентов, timeline, Rescue Queue и ограниченное число сортировок. Устаревший фоновый ключ дополнительно сверяется с текущей версией, чтобы не затереть более новый анализ.
- Из async-хендлеров убраны прямые DB/CPU/network-вызовы: анализ, настройки, snapshot, metrics, уведомления, сессии, scrypt/Basic, OIDC discovery/token/JWKS и остановка симулятора идут через `asyncio.to_thread`. OIDC получил lock вокруг discovery-cache, streaming-ответ с лимитом 1 МБ и кэшируемый `PyJWKClient`.
- Убраны найденные горячие места вокруг ядра: квадратичный поиск клиента в `sync_alerts`, перезапись неизменных alert-эпизодов и monitor-state, несколько COUNT вместо одного агрегата, полная загрузка снимка ради контактов одного DEMO-клиента, повторные realtime count-запросы, лишняя копия канонических snapshot-строк и двойной JSON encode при замене снимка.
- SQLite-политика стала явной: WAL, `synchronous=NORMAL`, busy timeout 15 c, cache 16 MiB, autocheckpoint и checkpoint при shutdown. В README честно зафиксирован durability-компромисс `NORMAL`, способ включить `FULL`, правила backup и почему несколько worker-процессов для SQLite не рекомендуются.
- На фронте первая страница при сортировке score/desc выводится из уже запрошенного top-100 без дублирующего `/customers`, volatile `generatedAt` исключён из polling-signature, а хэшированные Vite-ассеты получили `Cache-Control: public, max-age=31536000, immutable` только для успешных 2xx-ответов.

### Этап 2: PostgreSQL без отказа от SQLite

- Добавлен `churnrisk/database.py`: единый Row/Cursor/Connection-слой, SQLite как zero-config default и PostgreSQL при `DATABASE_URL=postgresql://...`/`postgres://...`. Для PostgreSQL используются psycopg 3, ограниченный пул процесса, трансляция qmark-placeholder, `INSERT OR IGNORE`, identity `RETURNING id`, `REAL → DOUBLE PRECISION`, `LIKE → ILIKE` и экранирование литерального `%` для клиентского биндинга psycopg.
- Живой PostgreSQL-прогон поймал реальный баг, который SQLite прощал: неоднозначную колонку `value` в metadata UPSERT. Источник и транслятор исправлены на квалифицированную `metadata.value`, добавлен регрессионный тест.
- Первая DDL-инициализация PostgreSQL сериализуется `pg_advisory_xact_lock`, чтобы реплики не гонялись на `CREATE ... IF NOT EXISTS`. Identity базы различает Unix-socket/query options без сохранения пароля; невалидный порт возвращается как конфигурационная ошибка. Явный SQLite `:memory:` теперь работает как одна shared-cache база процесса, а не как новая пустая БД на каждое короткое соединение.
- Добавлены `psycopg[binary,pool]`, pass-through env в Compose и опциональный профиль `postgres` (PostgreSQL 16 Alpine, named volume, healthcheck). Автоматической миграции данных SQLite ↔ PostgreSQL нет; это зафиксировано как ограничение, а не замаскировано.

### Полное ревью попутно исправило

- Критичный fail-open в Basic-auth: при пустом `ADMIN_PASSWORD` пустой пароль раньше мог сравняться с пустой конфигурацией. `verify_admin()` теперь fail-closed при пустом username или password, а ожидаемый scrypt-хеш кэшируется без хранения попыток входа.
- README в `main` буквально обрывался строкой `...[truncated 6111 chars]` посреди формата снимка. Хвост восстановлен и обновлён: алиасы/лимиты, SQLite/PostgreSQL, локальный запуск, тесты, OIDC, расширение модели и ограничения. Заодно исправлен невалидный пример транзакции (`status: success` без `type`).
- Приватные `_serviceFacts` проверены по всем публичным и персистентным путям: API отдаёт клиентов только через whitelist `_public_customer`, а alerts/realtime сохраняют скалярные payload, поэтому факты наружу не утекают.

### Измерения и проверка

- Чистый доменный бенчмарк финального кода в песочнице: 1k аккаунтов — analyze 0,009 c + summary 0,001 c; 10k — 0,094 + 0,007 c; 100k аккаунтов / 200k услуг / 300k транзакций — 1,394 + 0,061 c, peak RSS около 431 MiB в процессе бенчмарка. Это локальная синтетика, а не SLO.
- Отдельный DB-бенчмарк на 100k/200k/300k: одноразовая замена снимка с материализацией фактов — 6,632 c. Совместимый raw-путь после этого: загрузка JSON 1,975 c + analyze/summary 1,639 c. Prepared cold load: 2,495 c + scoring/summary 0,704 c. Главный выигрыш — смена весов поверх уже закэшированного prepared-снимка: остаются scoring/summary без повторной загрузки и парсинга транзакций. Cold load не стал на порядок быстрее, потому что raw-услуги всё ещё нужны карточкам и Rescue Queue.
- `ruff 0.17.2 check code.py churnrisk tests` — чисто. Полный unittest-набор расширен с 27 до 35 тестов и проходит **35/35 на SQLite** и **35/35 на живом embedded PostgreSQL** в отдельном процессе. Frontend build — 533 модуля; крупнейшие ассеты: vendor JS 356,10 КБ (113,26 КБ gzip), CSS 177,63 КБ (31,53 КБ gzip).
- Живой Uvicorn на порте 8000: `/health`, `/login`, providers, login, `/`, customers, summary, rescue-queue, notifications, realtime status, settings и `/metrics` отвечают 200; хэшированный JS получает immutable cache header. Docker/Compose в песочнице недоступны, поэтому Compose проверен только как YAML и по конфигурации, а не запуском.
- Реальный headless Chromium (npm-пакет `@sparticuz/chromium`, библиотеки из его AL2023-бандла) отрендерил логин и авторизованный дашборд без console/page errors. На desktop сцена логина держит пропорцию `2.222`: `755×340` при `1920×1080`, `612×276` при `1366×768`, `459×207` при `1024×768`; горизонтального/вертикального overflow на desktop нет. При `390×844` сцена `338×193` (`1.75`), а страница честно переходит в stacked-scroll с формой под hero. FPS этим прогоном не измерялся: headless SwiftShader не является репрезентативным GPU/refresh-rate стендом.

Итог ревью: узкое место сместилось с повторного парсинга/сканирования на фундаментальную стоимость хранения полного портфеля и prepared-фактов в памяти процесса. Следующий архитектурный шаг при росте — не автоматический Rust, а сначала лимиты/профилирование памяти, внешний или разделяемый кэш анализа и только затем PyO3/Axum для доказанно горячего ядра.

## Дополнение 17 — логин без вертикального растяжения и архитектурный вывод по бэкенду

По двум скриншотам пользователя исправлен полноэкранный логин: оболочка по-прежнему занимает `100dvh`, но hero-visual больше не является гибкой строкой, которая тянет mock-бары и карточку Aéza-тян только по высоте. Теперь это сцена с фиксированной пропорцией (`20/9` на desktop, отдельные пропорции для tablet/mobile): целевая высота ограничена `clamp(210px, 36dvh, 340px)`, ширина выводится из той же пропорции, колонка маскота занимает стабильную долю сцены, а бары — стабильную долю внутренней высоты mock-карточки. Лишняя высота панели распределяется пустыми grid-строками вокруг группы copy + visual, а не внутрь карточек. Проверка этой итерации: frontend build — 533 модуля, живой `/login` и `/api/v1/auth/providers` на порте 8000 отвечают 200; финальная геометрия позже подтверждена реальным headless Chromium в дополнении 18.

Отдельно проанализирован вопрос «переписать бэкенд на Rust или остаться на текущем стеке». Вывод: **полный Rust-rewrite сейчас преждевременен**. Текущий Python-бэкенд — около 5,2 тыс. строк (`FastAPI + Uvicorn + Pydantic + SQLite`), а измеренное узкое место находится не в HTTP-каркасе: чистый `domain.analyze + summary` на синтетике занимает примерно 0,02 + 0,003 с для 1 тыс. аккаунтов, 0,21 + 0,03 с для 10 тыс. и 2,53 + 0,37 с для 100 тыс. аккаунтов / 200 тыс. услуг / 300 тыс. транзакций (без загрузки JSON из SQLite, HTTP и Pydantic). Дороже всего архитектурная цепочка: `load_source()` читает и парсит все JSON-строки снимка, `analyze()` многократно сканирует услуги и парсит даты, а синхронный `_analyzed_data()` на cache miss вызывается из async-хендлеров и может блокировать event loop; single-flight вокруг вычисления нет. SQLite при этом открывается короткими соединениями без явного WAL в коде.

Рекомендуемый порядок усиления без смены языка: вынести анализ в `asyncio.to_thread` и защитить single-flight/stale-while-revalidate; материализовывать признаки и скоры при загрузке снимка/смене весов, а не пересчитывать весь снимок по TTL; один раз превращать JSON в типизированные агрегаты и даты — в epoch/day offsets; осознанно включить WAL с выбранным уровнем durability и резервным копированием; переходить на PostgreSQL только при нескольких репликах/хостах или устойчивой конкуренции писателей. Rust имеет смысл staged-вариантом: сначала PyO3-ядро только для `analyze` либо read-only Axum-sidecar для аналитики поверх материализованных таблиц и контрактных тестов. Полный Axum-порт оправдан, только если после этих оптимизаций профилирование всё ещё покажет недостижимые SLO по CPU, p95/p99 или памяти: переписывать придётся не один скоринг, а также auth/OIDC, SSE, realtime/outbox, схемы/OpenAPI и SQLite-логику. У схожих churn-проектов тренд подтверждается: FastAPI обычно оставляют, а усиливают PostgreSQL, объяснимый ML (XGBoost/LightGBM + SHAP), журнал исходов, калибровку, drift-мониторинг и CLV/uplift-приоритизацию. Для «Контура» ML допустим только рядом с текущими объяснимыми правилами и только после появления исторических разметок фактического оттока.

## Дополнение 15 — floating topbar, логотип-поглощение é, Live Dev Panel и Autopilot Aéza-тян

1. **Floating topbar.** Топбар больше не является полноширинной полосой: это sticky-плавающая поверхность с отступом от краёв viewport, полной рамкой, тенью и анимируемым радиусом (`clamp(25px, 2.1vw, 34px)` в покое, `22px` после скролла). Scroll-состояние обновляется только при пересечении порога и через `requestAnimationFrame`, поэтому лишних React-рендеров на каждый scroll-event нет.
2. **Синхронизация переехала из sidebar.** Старый нижний блок sidebar удалён. Стиль и текст «Снимок синхронизирован / Проверка каждые 10 сек.» перенесены в топбарную капсулу вместе с относительным временем обновления и прежней логикой `connectionError`.
3. **Логотип Aéza вокруг общего é.** `AnimatedAezaLogo` не перерисовывает буквы шрифтом: официальный `aeza-logo.svg` разрезан на четыре исходные keycap-плитки. При сворачивании `a/z/a` уезжают и уменьшаются в плитку `é`, затем официальный `aeza-symbol.svg` вырастает до rail-размера. При разворачивании символ сначала сжимается в слот `é`, остальные плитки рождаются из него наружу. На среднем breakpoint CSS принудительно держит компактный символ, неподвижная геометрия бренда не меняется.

### Live-монитор / Dev Panel

## Дополнение 13 — честно круглые углы контролов и актуальный README

Пользователь прислал разметку топбара (кнопка «Загрузить снимок», хлебные крошки, капсула синхронизации, переключатель темы): «тут не скруглены края». Диагностика подтвердила системную причину: в дизайн-токенах у всех кнопок Material Web и чипов один угол (end-start, нижний-левый) был специально меньше остальных (8px против 16px, у чипов 6 против 10) — «фирменный keycap-угол» из раунда стандартизации. На практике он читается не как фирменная деталь, а как дефект рендера, что пользователь и сообщал несколько раундов подряд («углы поломаны»).

Решение — убрать асимметрию у всех интерактивных контролов, а не только в топбаре:

- Токены `--shape-button`, `--shape-button-pressed`, `--shape-chip` стали одиночными значениями (16/10/10px) — нативные кнопки, сегменты, пилюли риска, чипы видов и легенды получили равные углы автоматически.
- Per-corner переменные Material Web (`--md-filled-button-…-end-start` и аналоги tonal/outlined/text, input/assist/filter chip) выровнены с остальными углами; комментарий в tokens.css объясняет, почему асимметрия удалена.
- Топбар доведён до честно круглого: кнопка загрузки — полная пилюля (все четыре per-corner значения 9999px именно на `.upload-button`), капсула синхронизации — `var(--shape-full)`, чип AÉZA — пилюля, переключатель темы — настоящий круг (50%; hover-морф в cookie и pressed-состояние сохранены).
- Та же асимметрия убрана у кнопки входа на логине (18px везде).
- Симметричные выразительные формы не тронуты: keycap-плитки (32% со всех сторон), cookie-рамка маскота и fan-морфы тамбов на время драга — они не выглядят «сломанными», потому что симметричны или явно анимированы.

README переписан под текущее состояние репозитория: быстрый старт с явным портом 8000 (и как получить 8080 через `PORT`), таблица модели из шести признаков с весами и формулами скора/денежной оценки, полная таблица эндпоинтов включая OIDC и churn-timeline, список всех Prometheus-метрик, актуальная карта файлов (oidc.py, snapshot.py, security.py, config.py), честный раздел тестов (нужны тестовые `ADMIN_*`, рекомендуется временный `DATABASE_PATH` — раньше README неверно обещал, что тесты не трогают базу). Заодно исправлены три давних Ruff-замечания (I001, TRY004 с расширением перехвата в storage, SIM117), поэтому `Ruff check code.py churnrisk tests` из README теперь действительно проходит.

Проверка: `npm run build` чисто (530 модулей, CSS `index-CUu9NCNS.css`); в собранном CSS end-start углы равны остальным (16/18/9999px по контекстам), `--shape-button: 16px`; unittest 23/23 на временной базе; Ruff clean; живой сервер отдаёт новый CSS, `/login` 200. Визуальный вердикт по углам — за живым превью.

## Дополнение 12 — раунд 4: плавность, читаемость, OIDC и график «факт vs прогноз»

Отзыв пользователя: «углы верхнего [чипа] поломаны», кнопка загрузки нестабильна, «всё на странице нестабильно, не плавно, как будто меньше 30 FPS», читаемость точечного числа — «ужас». Плюс промпт работодателя: обязательные критерии приёмки и бонусные OIDC + график оттока.

### Корень «<30 FPS» найден и устранён

- **Spotlight панелей** перерисовывал фон каждой панели за курсором: `pointermove` писал `--mx/--my/--spot`, фон — радиальный градиент с `calc(var(--spot)…)`, плюс переход зарегистрированного `@property --spot`. Это repaint большой поверхности на каждый кадр движения мыши. Spotlight удалён полностью (JS-обработчик, градиент, `@property`, оба перехода) — у панелей статичная поверхность и дешёвый hover по границе.
- **RiskStream** бесконечно переписывал `d` трёх SVG-путей (до 120 раз/с) — единственная некомпозиторная анимация страницы сажала главный поток. Теперь геометрия рисуется только на морф при смене данных (spring по `d`), а «живой» дрейф — CSS-трансформ всей группы (`stream-drift`, композитор, нативная частота дисплея). В покое — ноль перерисовок путей; единственный оставшийся rAF — троттлинг hover-состояния.
- **DotNumber удалён**: ~200 SVG-кружков с переходами и setState на каждый тик пружины. Сумма в RiskStream — крупная типографская цифра Exo 2 (`AnimatedNumber`, запись прямо в DOM без ре-рендеров), читаемость вместо точечной матрицы.

### Визуальные фиксы по скриншотам

- Чип AÉZA в топбаре: асимметричные углы `8px 12px 8px 5px` → единый `var(--shape-md)`.
- Кнопка загрузки: слои подписи больше не ездят и не масштабируются (был `y:6, scale:.92` на пространственной пружине) — только opacity-кроссфейд на effects-пружине M3; ширина по-прежнему зарезервирована невидимым сайзером, коробка кнопки неподвижна во всех фазах.

### Бонус работодателя №1: OIDC

- `churnrisk/oidc.py`: Authorization Code + PKCE (S256), discovery с кэшем, проверка ID-токена по JWKS (подпись, `iss`, `aud`, `exp`, `nonce`), опциональный allowlist `OIDC_ALLOWED_USERS`. `state/nonce/code_verifier` — серверные, одноразовые, 10 минут (таблица `oidc_states`).
- Эндпоинты: `GET /api/v1/auth/providers` (публичный), `GET /api/v1/auth/oidc/login`, `GET /api/v1/auth/oidc/callback`. Успешный вход создаёт ту же сессионную cookie, что и парольный. Парольный вход остаётся fallback; добавлен HTTP Basic для API-клиентов. На странице входа кнопка SSO появляется автоматически при настроенном провайдере; ошибки потока возвращают на `/login?oidc_error=1` с понятным сообщением.
- Зависимости `httpx` и `PyJWT[crypto]` добавлены в `requirements.txt`, импорты ленивые — без них приложение стартует, OIDC честно отвечает 503. Переменные проброшены в `.env.example` и `docker-compose.yml`.

### Бонус работодателя №2: график оттока «факт vs прогноз»

- `domain.churn_timeline()` + `GET /api/v1/analytics/churn-timeline`: факт — удаления (`status=deleted`, дата `deletedAt`, иначе `expiresAt`) по бакетам −90…−1 дн.; прогноз — услуги под риском (`prolong_wait`, истекающие без автопродления или у клиентов medium/high) и ожидаемые непродления (взвешены теми же коэффициентами 0,80/0,45/0,15, что и денежная оценка) по бакетам 0…90 дн.
- Панель «Динамика оттока услуг» на обзоре: сплошные малиновые столбцы факта, штрихованные столбцы прогноза, оранжевый маркер ожидаемых непродлений, пунктирный разделитель «сегодня», легенда и методика текстом. Столбцы анимируются только `scaleY` (композитор).
- Алиасы `deletedAt/deleted_at/removedAt` добавлены в нормализацию снимка; поле отдаётся в публичной карточке услуги.

### Метрики и обязательные критерии

- `/metrics` дополнен согласованными показателями из того же расчёта: `churn_monthly_revenue_at_risk_eur`, `churn_average_score`, `churn_services_at_risk(_30d)`, `churn_expected_nonrenewals_30d`, `churn_deleted_services_90d`, `churn_forecast_services{horizon_days}`.

- Новые маршруты и схемы внесены в `openapi.yaml`; README обновлён (OIDC-раздел, метрики, эндпоинты, ограничение про роли).

## Дополнение 11: возвращённые морфы состояний, cookie-фигура маскота, фикс кнопки загрузки и комплексная оптимизация плавности

По третьему кругу обратной связи (скриншоты: иконки рейла навигации, сегмент-фильтр риска, сцена маскота, кнопка «Загрузить снимок», референс M3 Expressive и ручка слайдера после клика по пустой области):

- **Слайдер больше не «квадратится».** Ручка в покое была keycap-squircle (32%): во время нажатия/фокуса она становилась капсулой, а после клика по пустой области (blur) возвращалась в «квадрат». Теперь ручка в покое — настоящий круг (50%, как в M3), капсула появляется только пока контрол реально нажат (`data-dragging`) или сфокусирован с клавиатуры (`:focus-visible` через `:has`); состояние `data-focused` от любого мышиного фокуса удалено из компонента и CSS, добавлен `onLostPointerCapture` для надёжного завершения драга. Тонкое кольцо цвета поверхности отделяет голубую ручку от голубой волнообразной дорожки, чтобы они не сливались в одно пятно.
- **Возвращены анимации переходов между состояниями (фото 1–2).** Все drag-select тамбы (пилюля навигации, мобильная навигация, сегмент-фильтр, легенда доната) снова морфят форму при удержании: стандартная фигура → fan-асимметрия 24/14 (у навигации 26/16) на shape-кривой, а не «pressed-квадрат» из прошлого слоя. Иконка-плитки навигации морфят keycap→clover при hover (раньше — только в активном состоянии), подпись выбранного сегмента мягко масштабируется, риск-точка в сегменте увеличивается при выборе; мобильные иконки получили тот же shape-transition. Путешествие тамбов по-прежнему делают пружины по transform, форма — интерполируемый border-radius на маленьких элементах.
- **Фигура маскота — как в референсе M3 Expressive (фото 3 vs 5).** Портретная арка заменена на cookie-blob: введён токен `--shape-cookie-portrait` (та же волнообразная blob-геометрия, но умеренные вертикальные радиусы, чтобы на высокой рамке голова, ноги и бейдж не срезались кривой) и его alt-вариант; рамка сцены на дашборде и карточка маскота на логине морфят cookie→cookie-alt при hover. Токен `--shape-arch` остался в шкале, но больше не используется; комментарий shape-системы обновлён.
- **Починенная вёрстка кнопки загрузки (фото 4).** У глифа загрузки внутри `md-filled-button` вообще не было CSS-размера (размер задавался только обёрткам `.md-icon-wrap`, а здесь иконка лежит прямо в слоях подписи) — SVG схлопывался и кнопка оставалась голым текстом со сбитым оптическим центром. Теперь иконки слоёв и скрытого sizer'а явно 18×18, `line-height: 1` у стека подписи держит иконку и текст по центру 42px-пилюли во всех трёх состояниях (idle/loading/success).
- **Комплексная оптимизация и плавность.** Постоянные `will-change` сняты с поверхностей, которые анимируются только по событию (слои иконки темы, ручка/трек слайдера, пилюли и плитки навигации, сегмент-тамб, line-mask логина): промоушн слоя теперь только у непрерывных циклов и на время активного драга (`.drag-select[data-dragging] .drag-thumb`). Остальные принципы сохранены: пружины от настенного времени, transform/opacity/clip-path, паузы вне вьюпорта и при reduced-motion (новые морфы в reduced-motion отключаются).

## Дополнение 10: кастомные M3 Expressive-слайдеры, волна темы от кнопки, живой RiskStream и полный expressive-проход

По второму кругу обратной связи со скриншотами (10 фото) и уточнённым ответам пользователя: слайдеры заменены на кастомный M3 Expressive-компонент, тема раскрывается круговой волной именно от кнопки, волна стрима постоянно течёт, а по всему интерфейсу сделан полный expressive-проход в духе референсов Google/M3 Expressive — поверх брендбука Aéza и стандартизированной шкалы углов из дополнения 9. Дополнительно задействованы M3 Foundations: design tokens как единый источник геометрии/цвета, interaction states с двумя визуальными индикаторами состояния, adaptive layout без выхода действий за viewport и доступность (клавиатура, фокус, reduced-motion).

- **Слайдеры переписаны (`ExpressiveSlider`).** `md-slider` удалён из регистрации Material Web, типов и токенов: у Material Web нет Expressive-слайдера, а стандартный мог показывать ручку не на текущем значении до hover. Новый компонент держит настоящий нативный `input[type=range]` для клавиатуры/тача/скринридеров, но рисует крупный волнообразный активный трек (mask-волна, раскрывается clip-path), морфирующую ручку (keycap-плитка → узкая вертикальная капсула при drag/focus, как в M3 Expressive) и постоянную плашку значения у ручки — состояние видно всегда: в покое, при hover, drag и с клавиатуры. Движение ручки — пружина standard-fast по настенному времени, бизнес-значение применяется мгновенно из нативного события. Заменены оба места: веса модели и калькулятор спасённой выручки; у весов убран remount-«поп» чипа на каждое целое значение при драге.
- **Тема — круговая волна от переключателя + синхронный морф иконки.** `toggleTheme(origin)` получает центр кнопки; в Chromium новая тема раскрывается `View Transitions` clip-path-кругом от этой точки на весь экран (720 мс, emphasized). Иконка больше не selected-слот `md-icon-button`: это кастомная кнопка, где солнце и луна одновременно вращаются/масштабируются/кроссфейдятся за те же 720 мс; отдельный `view-transition-name` у стека иконки анимирует снапшоты в том же ритме. Без View Transitions или при reduced-motion тема переключается сразу, морф иконки остаётся честным fallback без волны.
- **RiskStream ожил и перестал дёргаться по бакетам.** Волна теперь постоянно течёт: один rAF пишет `d` трёх SVG-путей напрямую (без ререндеров React), фаза — от настенного времени, общий swell-фактор и дрейф центра для всех кумулятивных слоёв не дают полосам пересекаться. Цикл останавливается вне вьюпорта, в скрытой вкладке и при reduced-motion. Hover стал непрерывным: позиция указателя превращается в дробную координату между центрами бакетов, направляющая едет на пружинном motion value, readout интерполирует значения так же, как сама кривая между центрами; обновления состояния троттлятся одним rAF. Панель стрима сведена к стандартному радиусу `--shape-xl` с `overflow:hidden` — острых/разных углов подложки не осталось.
- **Топбар не выпускает действия за край.** Хлебные крошки стали сжимаемой зоной с эллипсисом, капсула синхронизации раньше прячет время (≤1380px) и подпись (≤1180px), у действий и кнопки загрузки заданы min/max-width правила, `body` получил `overflow-x: clip` как страховку от горизонтального переполнения. Кнопка «Загрузить снимок» больше не должна упираться в край экрана ни на десктопе, ни на средней ширине.
- **Маскот парит по синусу.** `float-soft` заменён на `float-sine`: alternate-анимация cubic-bezier(.37,0,.63,1) без скачка производной в точках разворота, амплитуда уменьшена до −4px, полупериод ~4,8–5,2 с у изображений маскота. Тот же синусный ритм получили прочие `float-loop` (орбы и чипы логина стали заметно медленнее), `will-change/backface-visibility` держат движение на композиторе; reduced-motion полностью выключает парение.
- **Плашка «Снимок синхронизирован» стандартизирована.** Фирменный паттерн-«полоса» удалён из сайдбар-плашки и в JSX, и по смыслу: это теперь обычная карточка как остальные поверхности (`--md-surface-lowest`, стандартная граница, `--shape-lg`, обычная elevation), сигнал-точка — стандартный семантический акцент низкого/высокого состояния.
- **Полный M3 Expressive-проход по ролям, а не случайными фигурами.** Крупная hero-цифра KPI увеличена до display-размера; нативные кнопки/ссылки/CTA и тамб segmented при нажатии морфятся в pressed-форму; карточки получают согласованный hover по границе; заголовки панелей и подписи контролов защищены от переполнения (`min-width:0`, `overflow-wrap`); логин сведён к токенам шкалы (`--shape-xxl/xl/lg`) вместо случайных 64/54px. Существующие expressive-роли (keycap/cookie только на квадратных плитках, арка только у портрета маскота, wavy-трек слайдера, морфинг иконок навигации/аватаров/loader) сохранены и теперь образуют одну систему.

Проверка: `npm run build` чисто (530 модулей; чанк material уменьшился после удаления `md-slider`; CSS 22,0 КБ gzip); unittest 18/18 в отдельном venv; живой Uvicorn — `/login`, auth и `/api/v1/analytics/summary` 200 (сид 8 клиентов, 13111 евроцентов, 2/3/3), новые JS/CSS-ассеты 200. Статический аудит по пунктам обратной связи — 17/17: нет `md-slider`, слайдер на нативном range с `aria-valuetext`, волна темы и origin клика на месте, в сайдбаре нет паттерна, у стрима есть rAF/IntersectionObserver/visibility-паузы и непрерывный hover, в собранном CSS присутствуют slider/float-sine/theme-markers. Честно: браузерного скриншот/FPS-аудита в песочнице по-прежнему нет — плавность драга слайдера, волна темы и течение стрима окончательно подтверждаются только в живом превью.

## Дополнение 9: фикс визуальных багов, стандартизация фигур, официальные M3 motion-токены, оптимизация под 60–360 Гц

По скриншотам пользователя (квадратные кнопки без подписей, арка маскота режет текст, «капсула» выбранной строки RiskBars, остриё стрима, сломанный € в точечном числе, плита-тоггл сайдбара) проведён полный аудит. Нашлись два системных бага Material Web и класс проблем «выразительная фигура на широком текстовом контейнере»:

- **Баг 1 — квадратные кнопки.** Material Web разрешает форму кнопки ПО УГЛАМ (`--md-*-container-shape-start-start` и т.д.). Мы скармливали в `--md-*-container-shape` 4-значный шортхенд `18px 26px 18px 10px` — каждая угловая декларация становилась невалидной и падала в 0. Теперь фирменный «keycap-уголок» расписан по углам (16/16/16/8), а сам `container-shape` — валидный одно-значный фолбэк. То же для чипов; ручка слайдера — стандартный full.
- **Баг 2 — кнопки без подписей.** `.md-icon-wrap { width:100%; height:100% }` перебивал `::slotted`-размер иконки Material Web, растягивался на всю кнопку и сжимал подпись (overflow:hidden) в ноль — поэтому «Открыть Risk Inbox» был голой стрелкой. Теперь враппер размером с глиф (20px, в icon-button 24px). Этот же баг сидел в кнопке входа и всех кнопках с иконкой.
- **Стандартизация фигур.** Шкала углов — официальная M3 corner scale одиночными значениями (4/8/12/16/20/28/32/48/full); `--md-sys-shape-corner-*` совпадают с ней точно. Асимметрия осталась ровно одна — keycap-уголок на кнопках/чипах/навигации. Панели, карточки и строки — всегда равномерная шкала (fan/gem/panel-alt и прочие алиасы сведены к ней); cookie/clover/keycap-проценты — только на маленьких КВАДРАТНЫХ плитках; убраны случайные фигуры по nth-child у KPI-иконок, фигуры аватаров/точек по уровню риска (M3: форма не семантика — уровень несёт цвет), «капсула» выбранной строки RiskBars и cookie-морфы на широких тамбах drag-select.
- **Маскот-фигура.** Карточка Aéza-тян больше не арка целиком (999px углы на широкой карточке дугой проходили сквозь заголовок): карточка — стандартный радиус панели (28px), текст в прямоугольной безопасной зоне, а арка — портретная медиа-рамка только вокруг маскота, паттерн внутри рамки. Тоггл сайдбара — нормальная тональная кнопка с иконка-плиткой, в рейле — квадратная 44px icon-кнопка вместо плиты.
- **RiskStream/DotNumber.** Убрана маска-градиент, рисовавшая ложное остриё; поток честно сходится в кончики у обоих краёв (виртуальные нулевые точки), контрольные точки сплайна зажаты в диапазон сегмента (нет «плеч» выше данных). Глиф € перерисован, счётчик — критически демпфированная пружина ~0,6с вместо двухсекундного ползания, ширина резервируется по финальному значению (нет прыжков вёрстки). Readout — отдельная чип-плашка, активная подпись оси подсвечивается, ховер-линия ограничена телом потока.
- **Motion по официальным источникам M3** (motion physics system, easing/duration, transition patterns — страницы из задания + токены androidx Compose Material3): `motion.ts` переписан на настоящие spring-токены expressive/standard × spatial/effects (k и ζ конвертированы в Framer Motion c=2ζ√k); opacity едет на effects-пружинах без овершута, выходы — emphasized-accelerate 200мс; переходы страниц — top-level fade-through вместо бокового слайда, пагинация списка — lateral. В CSS исправлен `--motion-emphasized` (был ошибочно равен decelerate) и добавлена шкала длительностей M3.
- **Стабильность на 60/120/165/240/360 Гц.** Пружины интегрируются от настенного времени — длительность не зависит от частоты, высокая герцовка просто сэмплирует плавнее. Убрано всё, что красит каждый кадр бесконечно: shape-breathe (border-radius-анимация плиток), дрейф паттерна, все бесконечные JS-rAF циклы Framer Motion переведены на CSS transform-анимации (композитор) с параметрами через CSS-переменные; удалены все backdrop-blur (поверхности и так ~95% непрозрачны) и лишние постоянные `will-change`.

Проверка: `npm run build` чисто (CSS 20,0 КБ gzip); unittest 18/18; живой Uvicorn — login/auth/summary/ассеты 200, сид 8/13111. Статический визуальный аудит скриптом: все `--md-*-shape` валидны по углам, шкала углов точно M3, контрасты ключевых пар обеих тем ≥4,5 (посчитаны по WCAG), арка осталась только в двух портретных рамках; геометрия стрима и точечное число отрендерены через resvg на сид-данных — чисто. Честно: полноценный браузерный скриншот/FPS-замер в песочнице по-прежнему недоступен (нет браузерных системных библиотек) — финальный вердикт за живым превью, особенно подписи кнопок и сцена маскота. Отдельно: свежий ruff 0.17.2 нашёл 3 замечания в нетронутом бэкенде (`churnrisk/snapshot.py`, `tests/test_domain.py`) — не из этого PR, оставлено как есть.

## Дополнение 7: сворачиваемый сайдбар, адаптивный масштаб, сглаживание, «живость» и оптимизация

## Дополнение 3: аудит переходов, продающий обзор, 3D-карта риска, what-if и инбокс

Третья итерация: сначала стабилизация анимаций, затем продуктовые фичи из бэклога.

### Аудит нестабильных переходов (найдено и исправлено)

- **Иконка темы «улетала».** Причина: `AnimatePresence mode="popLayout"` делает уходящий элемент `position: absolute`; если ближайший родитель не позиционирован, элемент «прилипает» к дальнему позиционированному предку (sticky-топбару). Переключатель темы получил `position: relative; overflow: hidden` и центрированную сцену 24px; вращение убрано с самой кнопки и смягчено (±35°, scale .65) на иконке. Та же причина лечила хлебные крошки, риск-пилюли и контейнер строк — теперь все родители `popLayout` позиционированы/содержат оверфлоу.
- **Снекбар прыгал по горизонтали.** CSS `transform: translateX(-50%)` конфликтовал с трансформами Framer Motion (Motion владеет `transform` и сбрасывает −50%). Центрирование теперь без CSS-трансформа (`left/right: 0; width: max-content; margin: auto`).
- **Кнопка загрузки снимка «схлопывалась».** Убраны `layout` + `mode="wait"` на подписях; смена состояний — содержащийся `popLayout`.

### Продающий лейаут обзора и фичи

- **Hero с призывом к действию:** кнопки «Открыть Risk Inbox · N» и «What-if: покрутить веса», золотой чип «Под угрозой на 90 дней: €…» с анимированной суммой.
- **3D-карта выручки под риском** (`RiskLandscape.tsx`). В снимках нет географии, поэтому карта — ландшафт данных, а не фейковая геокарта: каждый клиент — столбец CSS-3D (высота = выручка под риском за 90 дней, цвет = уровень, число сверху = score). Плоскость вращается зажатием/перетаскиванием (спринг за курсором), клик по столбцу открывает клиента в очереди. Цель — мгновенно видеть концентрацию денег, а не только счётчики клиентов.
- **Risk Inbox.** Страница «Клиенты» подаётся как рабочая очередь с приоритетом контакта; hero и «Очередь на сегодня» ведут прямо в неё.
- **«Объясни score»** (`FactorBreakdown` в карточке клиента): вклад каждого фактора в баллы считается из реальных `features` × `weights` (подписи — из `settings.features` API). Сумма вкладов ≈ score (расхождение ≤1–2 — округление, о чём UI предупреждает; проверено на живом клиенте: 93 против серверных 92).
- **What-if симулятор** (`simulate.ts` + `WhatIf.tsx`) — клиентское зеркало скоринга `domain.py`. Веса больше не автосейвятся: ползунки правят локальный черновик, панель мгновенно показывает дельты уровней/потерь и клиентов-«переезжантов»; сервер применяет веса только по кнопке «Применить веса» (PATCH) и остаётся источником истины.
- **Калькулятор спасённой выручки:** сценарий «удержим X% высокого и Y% среднего риска» поверх реальной сценарной оценки потерь; честно подписан как инструмент целеполагания, не прогноз.
- **Сохранённые фильтры и сегменты:** именованные виды очереди (фильтр+сортировка) с чипами, применением и удалением. Пока хранятся в localStorage и подписаны как локальные.
- **Центр качества данных:** индекс качества с кольцом, доля оценённых клиентов, клиенты без услуг/дат/с незавершёнными платежами и переход в фильтр «без оценки».
- **История риска портфеля:** точки (потери, число высокого риска) пишутся в localStorage только при реальном изменении сводки; график честно подписан как локальная история браузера.

Честные ограничения: карта, what-if, калькулятор и детализация качества работают по топ-100 клиентов по score (UI везде указывает «по загруженным N»); сервер при сохранении пересчитывает всех.

### Дорожная карта бэкенда (киллер-фичи следующего уровня)

1. **Серверный журнал снимков и score-history по клиенту** — таблица `score_snapshots` при каждой загрузке/`PATCH` весов → настоящая история Risk Score, тренды и алерты «клиент резко вырос в риске».

4. **Агрегаты без топ-100:** в `/analytics/summary` добавить потери по уровням и счётчики качества данных.
5. **География в снимке** (`country/region` у аккаунта) → из ландшафта делается настоящая 3D-геокарта выручки по регионам.
6. **Когорты и ретро-оценка модели:** доля фактически ушедших среди high-risk прошлых снимков — калибровка весов цифрами, а не вкусом.

Проверка: `npm run build` (tsc + Vite) — чисто; `python -m unittest` — 14/14; `ruff check`/`format` — чисто; живой Uvicorn: новый бандл под строгой CSP, вход/сводка (8 клиентов сида: 2/3/3, потери 13 111)/топ-100/настройки — 200; математика разбора score сверена с серверной на живом клиенте. В песочнице нет браузера, поэтому визуал и drag/3D-жесты нужно подтвердить руками в живом превью. Трансформации элементов (ядро редизайна, всё — `transform`/`opacity`, пружины M3 Expressive в `frontend/src/motion.ts`):

- строка клиента **разворачивается в карточку** прямо в списке: кольцо риск-скора, следующий шаг удержания, услуги; соседние строки скользят (FLIP `layout="position"` + `AnimatePresence popLayout`);
- сортировка **переставляет строки физикой**, смена страницы — направленный сдвиг, риск-пилюли морфируются при пересчёте весов;
- сегмент-фильтр риска со **скользящим ползунком** (`layoutId`), синхронизирован с SVG-донатом: сегменты морфируются пружинами, выбор сегмента фильтрует список;
- KPI-деньги **докручиваются спрингом** (`AnimatedNumber`), график продлений перерисовывает путь морфом `d`;
- навигация: скользящая пилюля активного раздела (сайдбар и мобильное дно-меню), тема: морф солнце↔луна, кнопка загрузки снимка: состояния idle→loading→success + drag-and-drop оверлей;
- логин: построчный ривил заголовка, плавающие лейблы M3-полей, шейк формы при ошибке, кнопка морфится в «Добро пожаловать».

Коммерческая подача: выручка под риском — тёмно-зелёный hero-блок бенто-сетки с CTA «Смотреть высокий риск» прямо в отфильтрованную очередь; в карточке клиента — блок «Следующий шаг» (выводится из уже существующих сигналов API, скоринг не меняется) и действия «копировать email / написать письмо». ## 1. Обзор проделанной работы

Платформа аналитики риска оттока клиентов переведена на систему **Material Design 3 (M3) и M3 Expressive**. ## 2. Архитектура дизайн-системы

### Цветовая палитра и роли поверхностей (M3 Semantic System)
В `static/design-tokens.css` выстроена система семантических ролей для светлой (`light`) и тёмной (`dark`) тем:
- **Primary / Primary Container**: Аналитический хвойно-бирюзовый тон (`#176853` / `#d2f2e6` в светлой теме; `#76d7b9` / `#00513d` в тёмной теме).
- **Secondary / Tertiary**: Сдержанные сланцевые и теплые охристые акценты для вспомогательных индикаторов и меток.
- **Иерархия поверхностей (Surface Roles)**:
  - `surface` (фоновое полотно): `#f7f9f7` (light) / `#0f1513` (dark).
  - `surface-container-lowest`: Чистый `#ffffff` (light) / `#0a0f0e` (dark) для карточек и модальных окон.
  - `surface-container-low`, `surface-container`, `surface-container-high`: Вспомогательные контейнеры для сайдбара, шапки и сгруппированных контролов.
- **Семантика уровней риска**:
  - **Высокий риск**: `#94251e` на `#fde8e5` (контраст > 5.5:1 в светлой теме; `#ffb4ab` на `#471410` в тёмной).
  - **Средний риск**: `#7a5300` на `#fef3d8` (контраст > 5.8:1 в светлой теме; `#fedc94` на `#3f2900` в тёмной).
  - **Низкий риск**: `#156746` на `#e0f6ec` (контраст > 5.4:1 в светлой теме; `#82d9aa` на `#003823` в тёмной).
  - **Без оценки**: `#4e5b55` на `#eef2ef` (контраст > 5.2:1 в светлой теме; `#b8c4be` на `#242c28` в тёмной).

### Типографика и табличные числа
- Автономный локальный шрифт **Manrope** (наборы Cyrillic и Latin в формате `woff2` в `static/fonts/`). Не требует внешних CDN и полностью удовлетворяет жесткой Content Security Policy приложения.
- Для всех числовых и финансовых показателей включены табличные пропорциональные цифры (`font-feature-settings: "tnum" 1, "lnum" 1`), обеспечивающие вертикальное выравнивание разрядов в таблицах и метриках.

## 3. Переработанные экраны и компоненты

### 1. Экран аутентификации (`/login`)
- Сбалансированная двухколоночная композиция с презентацией платформы и карточкой входа.
- Поля ввода с четкими лейблами, подсказками и видимым фокусом (`:focus-visible`).
- Добавлен переключатель светлой и тёмной темы непосредственно на странице логина с сохранением выбора в `localStorage`.
- Доступные сообщения об ошибках с `role="alert"` и анимация ожидания ответа сервера.

### 2. Главная панель аналитики (`/`)
- **Навигационный рейл**: Компактное боковое меню с активным индикатором M3, счетчиками разделов, статусом синхронизации снимка данных, профилем аналитика и кнопкой выхода.
- **Шапка (Topbar)**: Закрепленная панель с размытием фона (`backdrop-filter: blur(16px)`), динамическим индикатором статуса подключения, датой и кнопкой импорта снимка.
- **Сетка KPI (4 карточки)**:
  1. *Клиентов в анализе*: Общее число и процент оцененных клиентов.
  2. *Высокий риск*: Карточка с акцентной рамкой и предупреждающей меткой «Нужен контакт команды».
  3. *Выручка под риском*: Финансовая метрика 90-дневной сценарной оценки с форматированием в евро.
  4. *Услуги под риском*: Число услуг со скорым окончанием срока или ожиданием продления.

### 3. Таблица рейтинга клиентов
- Поддержка сортировки по всем полям (ID, клиент, баланс, пополнения, риск-скор) в обоих направлениях (ASC / DESC) с индикацией `aria-sort`.
- Селектор фильтрации по категориям риска с индикацией активного фильтра.
- Оптимизированное форматирование денежных сумм, бейджи уровней риска и текстовые причины срабатывания сигналов.
- Плавная пагинация с отображением текущего диапазона и блокировкой неактивных кнопок.

### 4. Аналитические визуализации
- **Диаграмма сегментов риска**: Conic-gradient диаграмма с вычислением сегментов в зависимости от текущей темы и интерактивной легендой.
- **Карточка сценарной выручки**: Четкое текстовое пояснение, что показатель является оценкой выручки за 3 месяца за вычетом баланса, умноженной на коэффициент категории риска.
- **График продления услуг (30 дней)**: Векторный SVG-график с плавной заливкой градиентом, разметкой осей и четким разделением фактических данных и прогноза к сроку.

### 5. Настройка весов модели риска
- Интерактивные слайдеры с диапазоном 0–100 и синхронизированные числовые поля.
- Оптимистичное обновление интерфейса и дебаунс сохранения (320 мс) через `PATCH /api/v1/model/settings`.
- Индикатор статуса синхронизации: отображает сохранение, успешную синхронизацию или ошибку сети.

### 6. Карточка детальной информации клиента
- Нативное диалоговое окно `<dialog>` с затемнением и размытием фона.
- Шкала оценки риска с визуальным прогресс-баром соответствующего цвета.
