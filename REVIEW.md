# Ревью и отчет о редизайне платформы аналитики риска оттока

## Дополнение 3: аудит переходов, продающий обзор, 3D-карта риска, what-if и инбокс

Третья итерация: сначала стабилизация анимаций, затем продуктовые фичи из бэклога.

### Аудит нестабильных переходов (найдено и исправлено)

- **Иконка темы «улетала».** Причина: `AnimatePresence mode="popLayout"` делает уходящий элемент `position: absolute`; если ближайший родитель не позиционирован, элемент «прилипает» к дальнему позиционированному предку (sticky-топбару). Переключатель темы получил `position: relative; overflow: hidden` и центрированную сцену 24px; вращение убрано с самой кнопки и смягчено (±35°, scale .65) на иконке. Та же причина лечила хлебные крошки, риск-пилюли и контейнер строк — теперь все родители `popLayout` позиционированы/содержат оверфлоу.
- **Снекбар прыгал по горизонтали.** CSS `transform: translateX(-50%)` конфликтовал с трансформами Framer Motion (Motion владеет `transform` и сбрасывает −50%). Центрирование теперь без CSS-трансформа (`left/right: 0; width: max-content; margin: auto`).
- **Кнопка загрузки снимка «схлопывалась».** Убраны `layout` + `mode="wait"` на подписях; смена состояний — содержащийся `popLayout`.

### Продающий лейаут обзора и фичи

- **Hero с призывом к действию:** кнопки «Открыть Risk Inbox · N» и «What-if: покрутить веса», золотой чип «Под угрозой на 90 дней: €…» с анимированной суммой.
- **3D-карта выручки под риском** (`RiskLandscape.tsx`). В снимках нет географии, поэтому карта — ландшафт данных, а не фейковая геокарта: каждый клиент — столбец CSS-3D (высота = выручка под риском за 90 дней, цвет = уровень, число сверху = score). Плоскость вращается зажатием/перетаскиванием (спринг за курсором), клик по столбцу открывает клиента в очереди. Цель — мгновенно видеть концентрацию денег, а не только счётчики клиентов.
- **Risk Inbox.** Страница «Клиенты» подаётся как рабочая очередь с приоритетом контакта; hero и «Очередь на сегодня» ведут прямо в неё.
- **«Объясни score»** (`FactorBreakdown` в карточке клиента): вклад каждого фактора в баллы считается из реальных `features` × `weights` (подписи — из `settings.features` API). Сумма вкладов ≈ score (расхождение ≤1–2 — округление, о чём UI предупреждает; проверено на живом клиенте: 93 против серверных 92).
- **What-if симулятор** (`simulate.ts` + `WhatIf.tsx`) — клиентское зеркало скоринга `domain.py`. Веса больше не автосейвятся: ползунки правят локальный черновик, панель мгновенно показывает дельты уровней/потерь и клиентов-«переезжантов»; сервер применяет веса только по кнопке «Применить веса» (PATCH) и остаётся источником истины.
- **Калькулятор спасённой выручки:** сценарий «удержим X% высокого и Y% среднего риска» поверх реальной сценарной оценки потерь; честно подписан как инструмент целеполагания, не прогноз.
- **Сохранённые фильтры и сегменты:** именованные виды очереди (фильтр+сортировка) с чипами, применением и удалением. Пока хранятся в localStorage и подписаны как локальные.
- **Центр качества данных:** индекс качества с кольцом, доля оценённых клиентов, клиенты без услуг/дат/с незавершёнными платежами и переход в фильтр «без оценки».
- **История риска портфеля:** точки (потери, число высокого риска) пишутся в localStorage только при реальном изменении сводки; график честно подписан как локальная история браузера.

Честные ограничения: карта, what-if, калькулятор и детализация качества работают по топ-100 клиентов по score (UI везде указывает «по загруженным N»); сервер при сохранении пересчитывает всех.

### Дорожная карта бэкенда (киллер-фичи следующего уровня)

1. **Серверный журнал снимков и score-history по клиенту** — таблица `score_snapshots` при каждой загрузке/`PATCH` весов → настоящая история Risk Score, тренды и алерты «клиент резко вырос в риске».
2. **Состояния Risk Inbox на сервере** — `assignee/state (new→in_progress→contacted→saved→lost)/snooze` + журнал действий → командная очередь вместо локальной.
3. **Сохранённые виды на сервере** и шаринг сегмента ссылкой (`?view=…`).
4. **Агрегаты без топ-100:** в `/analytics/summary` добавить потери по уровням и счётчики качества данных.
5. **География в снимке** (`country/region` у аккаунта) → из ландшафта делается настоящая 3D-геокарта выручки по регионам.
6. **Когорты и ретро-оценка модели:** доля фактически ушедших среди high-risk прошлых снимков — калибровка весов цифрами, а не вкусом.

Проверка: `npm run build` (tsc + Vite) — чисто; `python -m unittest` — 14/14; `ruff check`/`format` — чисто; живой Uvicorn: новый бандл под строгой CSP, вход/сводка (8 клиентов сида: 2/3/3, потери 13 111)/топ-100/настройки — 200; математика разбора score сверена с серверной на живом клиенте. В песочнице нет браузера, поэтому визуал и drag/3D-жесты нужно подтвердить руками в живом превью. Примечание: прогон тестов перезаписывает локальную `data/churn.db` тестовым снимком — для демо БД пересоздаётся из серверного сида при удалении файла.

## 0. Дополнение: React + Framer Motion, Material Design 3 Expressive (премиальная подача)

Интерфейс мигрирован с vanilla HTML/CSS/JS на **React 19 + TypeScript + Vite + Framer Motion 12** (`frontend/`, сборка в `static/app`). API, доменная логика, хранилище и серверный гейт аутентификации (`/` только с сессией, `/login` только без неё) не изменены; при отсутствии собранного бандла FastAPI отдаёт прежние vanilla-страницы.

Трансформации элементов (ядро редизайна, всё — `transform`/`opacity`, пружины M3 Expressive в `frontend/src/motion.ts`):

- строка клиента **разворачивается в карточку** прямо в списке: кольцо риск-скора, следующий шаг удержания, услуги; соседние строки скользят (FLIP `layout="position"` + `AnimatePresence popLayout`);
- сортировка **переставляет строки физикой**, смена страницы — направленный сдвиг, риск-пилюли морфируются при пересчёте весов;
- сегмент-фильтр риска со **скользящим ползунком** (`layoutId`), синхронизирован с SVG-донатом: сегменты морфируются пружинами, выбор сегмента фильтрует список;
- KPI-деньги **докручиваются спрингом** (`AnimatedNumber`), график продлений перерисовывает путь морфом `d`;
- навигация: скользящая пилюля активного раздела (сайдбар и мобильное дно-меню), тема: морф солнце↔луна, кнопка загрузки снимка: состояния idle→loading→success + drag-and-drop оверлей;
- логин: построчный ривил заголовка, плавающие лейблы M3-полей, шейк формы при ошибке, кнопка морфится в «Добро пожаловать».

Коммерческая подача: выручка под риском — тёмно-зелёный hero-блок бенто-сетки с CTA «Смотреть высокий риск» прямо в отфильтрованную очередь; в карточке клиента — блок «Следующий шаг» (выводится из уже существующих сигналов API, скоринг не меняется) и действия «копировать email / написать письмо». Дисклеймеры про эвристику сохранены.

Проверка этого этапа: `npm run build` (tsc + Vite, без инлайн-скриптов в `index.html` под строгой CSP), `python -m unittest` — 14/14, `ruff check`/`format` — чисто, живой Uvicorn: `/login` 200 с бандлом, ассеты/шрифты 200, анонимный `/` — 303, вход и все API — 200. ## 1. Обзор проделанной работы

Платформа аналитики риска оттока клиентов переведена на систему **Material Design 3 (M3) и M3 Expressive**. Вместо разнородных переопределений и устаревших стилей сформирована централизованная дизайн-система токенов, поддержаны светлая и тёмная темы оформления с автоматической и ручной синхронизацией, обновлены все пользовательские экраны и микроанимации при строгом сохранении существующей бизнес-логики и контрактов API.

## 6. Измененные файлы проекта

1. `static/design-tokens.css` — полная система дизайн-токенов Material 3 (светлая и тёмная темы).
2. `static/dashboard.css` — обновленные стили интерфейса аналитической панели.
3. `static/ui-redesign.css` — микроанимации, фокусные состояния и табличные числовые форматы.
4. `static/login.html` — разметка страницы входа с переключателем темы.
5. `static/login.css` — стили экрана входа в концепции M3 Expressive.
6. `static/login-redesign.css` — доступность полей ввода и фокусных колец.
7. `static/login.js` — логика переключения темы на странице входа.
8. `static/app.js` — динамическое обновление цветов диаграммы при переключении темы и анимация чисел.
9. `templates/index.html` — градиентные SVG-дефиниции для графиков и версионирование кэша.
10. `docker-compose.yml` — монтирование статики и шаблонов для обновления контейнера на лету.
11. `REVIEW.md` — настоящее ревью с полным описанием архитектурных и визуальных изменений.
